Deploying certifications.trevorwdunn.us

Cloudflare Pages + Pages Functions + D1, pointed at the GitHub repo.

Two things only you can do. Steps marked you need an interactive browser or terminal login, so they can't be automated. Everything else is clicking through the Cloudflare dashboard.

1Push the repo to GitHub you

The local repo is committed and ready on branch main. It just needs a remote. Authenticate the GitHub CLI first:

gh auth login

Then create the repo and push in one shot:

cd "C:\Users\Trevor\Documents\Claude\Projects\CompTIA Training\Certifications"
gh repo create comptia-certifications-study --public --source=. --push
Nothing sensitive is in the repo. wrangler.toml carries a placeholder database ID, and the JWT signing key is read from the environment at runtime — the code now refuses to issue tokens if that variable is missing, rather than falling back to a default that would be public.

2Create the D1 database

In the Cloudflare dashboard: Storage & Databases → D1 → Create database.

  1. Name it exactly certifications-db.
  2. Once created, copy the Database ID shown on its page.

Now create the tables. Open the database's Console tab and paste the contents of schema.sql, or run it locally:

npx wrangler d1 execute certifications-db --remote --file=schema.sql

You should end up with two tables: users and user_progress.

Redeploy after setting these. Cloudflare only applies new bindings and variables to new builds. Until you redeploy, sign-up and sign-in will fail.

5Point the domain at it

In the Pages project: Custom domains → Set up a custom domain, and enter:

certifications.trevorwdunn.us

Since trevorwdunn.us is already on Cloudflare, the CNAME is created for you and the certificate issues within a few minutes.

6Create the three accounts

Visit the site and register Trevor, Jack, and Billy through the normal sign-up form. Use the same email addresses that have Gravatars attached, since avatars are derived from a hash of the email — no images are stored anywhere.

The 404 you saw locally was expected. vite dev and vite preview serve static files only; they don't run Pages Functions, so /api/auth/register genuinely doesn't exist there. To exercise the API locally, use npx wrangler pages dev dist instead.

7Resetting a forgotten password

There's no self-serve reset flow yet, which is a deliberate choice for a three-person site with no domain mailbox. If someone gets locked out, delete their user row and have them register again — progress lives in a separate table keyed by user ID, so it's cleaner to reset the password than to lose the row.

To wipe an account entirely (progress included, via the cascade):

npx wrangler d1 execute certifications-db --remote \
  --command "DELETE FROM users WHERE email = 'someone@example.com'"

To check how many of the ten account slots are used:

npx wrangler d1 execute certifications-db --remote \
  --command "SELECT email, created_at FROM users ORDER BY created_at"

Proper email-based resets are the eventual plan. That needs a sending service such as Resend or Postmark plus DNS verification on trevorwdunn.us, so it's parked until there's a mailbox on the domain.

8Updating content later

Pages rebuilds on every push to main. Before pushing question or flashcard changes, run the content validator — it catches out-of-range answer indices, duplicate IDs and unknown domains, all of which fail silently in the UI:

node validate-content.mjs

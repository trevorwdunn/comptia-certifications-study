3Create the Pages project done

Done from the CLI rather than the dashboard, so the project is a direct upload and is not connected to GitHub. Pushing to main deploys nothing on its own.

npx wrangler pages project create comptia-certifications-study --production-branch main

To publish a change, build and upload:

npm run build
npx wrangler pages deploy dist --project-name=comptia-certifications-study

Live at comptia-certifications-study.pages.dev. If you'd rather have build-on-push, connect the repo under Settings → Builds & deployments; nothing in the code cares which mode is used.

4Bind the database and set variables done

The DB binding comes from wrangler.toml and is applied on every pages deploy, so there is nothing to click. The binding name must stay exactly DB — that's what the API functions reference.

JWT_SECRET is set as an encrypted secret. It was generated and piped straight into Wrangler so the value was never printed, written to a file, or shown in the transcript:

node -e "process.stdout.write(require('crypto').randomBytes(48).toString('base64url'))" | npx wrangler pages secret put JWT_SECRET --project-name=comptia-certifications-study

Nobody has a copy of that value, which is fine — it is never needed again. Replacing it is the same command, and doing so signs everyone out.

MAX_ACCOUNTS is not set, so the code's default of 10 applies. Set it in the dashboard under Settings → Variables only if you want a different cap.

Redeploy after changing any of these. Cloudflare only applies bindings and variables to new deployments.

Verified working: a sign-in attempt with a nonexistent account returns 401 Invalid credentials rather than a 500, which means the request reached D1.

5Point the domain at it you

Wrangler 4.x has no pages domain command, so this step is dashboard-only.

In the Pages project: Custom domains → Set up a custom domain, and enter:

certifications.trevorwdunn.us

Since trevorwdunn.us is already on Cloudflare, the CNAME is created for you and the certificate issues within a few minutes.

6Create the three accounts you

Visit the site and register Trevor, Jack, and Billy through the normal sign-up form. Nothing has registered yet, so all 10 slots are free. Use the same email addresses that have Gravatars attached, since avatars are derived from a hash of the email — no images are stored anywhere.

The 404 you saw locally was expected. vite dev and vite preview serve static files only; they don't run Pages Functions, so /api/auth/register genuinely doesn't exist there. To exercise the API locally, use npx wrangler pages dev dist instead.

7Resetting a forgotten password

There's no self-serve reset flow yet, which is a deliberate choice for a three-person site with no domain mailbox. If someone gets locked out, delete their user row and have them register again — progress lives in a separate table keyed by user ID, so it's cleaner to reset the password than to lose the row.

Easiest route is the Console tab on the D1 database in the dashboard. To wipe an account entirely (progress included, via the cascade):

DELETE FROM users WHERE email = 'someone@example.com';

To check how many of the ten account slots are used:

SELECT email, created_at FROM users ORDER BY created_at;

Proper email-based resets are the eventual plan. That needs a sending service such as Resend or Postmark plus DNS verification on trevorwdunn.us, so it's parked until there's a mailbox on the domain.

8Updating content later

Pages rebuilds on every push to main. Before pushing question or flashcard changes, run the content validator — it catches out-of-range answer indices, duplicate IDs and unknown domains, all of which fail silently in the UI:
